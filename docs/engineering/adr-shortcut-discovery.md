# Preserve intent identities across the module boundary

The production model, entity and action declarations remain in module `One`. The executable modules are `TodayApp` and `TodayMockApp`; their product/bundle identities are unchanged. The local Swift package identity is `ios` (the manifest display name is `TodayModules`). Development assembly targets use the compiler's matching package name to access package-only feature constructors; shipping assembly enters through public OneStore/TodayShell APIs.

Actual Xcode 27.1 builds exposed a metadata failure after extraction: all 12 actions survived, but executable `autoShortcuts` fell from five to zero. Merely declaring Apple's [AppIntentsPackage](https://developer.apple.com/documentation/appintents/appintentspackage) dependency did not restore discovery. Forwarding an array from a framework provider also failed the actual metadata processor, which requires AppShortcut builder syntax.

`Sources/One/TodayShortcuts.swift` is therefore one authoritative phrase declaration compiled in both the identity bridge and executable, like the existing separately compiled AlarmActivity identity source. It keeps the legacy `One.TodayShortcuts` declaration available and gives the executable its discovery provider. The application contains no duplicate action implementation. Five action APIs are public solely to support that executable declaration. No phrase, intent/entity name, schema, encoded model field or bundle identifier changed.

The real Debug App+Widget+Share build passed with no warnings in `tests/results/devtools/logs/d6c7f5424d804534b1b0a022e50f18dd.log`. Compared with original Release metadata, all action identifiers and complete actions (after sorting only resolvableInputTypes alternatives), five autoShortcuts, entity, enums and query definitions match. The executable discovery-provider mangled name changes with its module; the legacy provider declaration remains One-owned. Raw evidence: `tests/results/reconstruction/baseline/module-intents-comparison.json`. This proves generated metadata compatibility, not installed Shortcuts/Siri or physical-device upgrade behavior; those remain explicitly unverified.
