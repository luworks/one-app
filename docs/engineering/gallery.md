# Native reconstruction gallery adapter

This development-only library presents **real native PNG captures**. It does not
render app UI in HTML, synthesize fallback screenshots, build the app, select a
simulator, install software, or implement another native workbench. The existing
`scripts/swiftui_preview.py` and axe workflow are unchanged.

## Integration boundary

Root owns `./dev`, TodayScenes, the Workbench launch/screenshot implementation,
native scene registration, project and production sources. Root should generate
an explicit JSON manifest from the native TodayScenes registry, then call
`scripts.gallery.__main__.main(argv, root=worktree_root)` from its CLI, or use the
library below. The adapter does not discover scenes by scanning source code and
does not accept a command or executable in a manifest or HTTP request.

Schema 1 has exactly these fields (illustrative IDs; use native registry IDs):

```json
{
  "schema": 1,
  "locks": ["ios/Package.resolved"],
  "scenes": [
    {
      "id": "today",
      "scenarios": ["normal", "empty"],
      "sources": ["ios/One/DayAgenda.swift", "ios/One/Rows.swift"]
    }
  ]
}
```

`locks` may be empty; scenes, scenarios and source lists must be nonempty and
unique. IDs use `[A-Za-z0-9][A-Za-z0-9_.-]{0,79}`. Paths are explicit repository
relative files, with no absolute paths, empty components, dot components,
backslashes or final symlinks; resolved paths must stay inside the worktree.
Unknown fields and duplicate scene IDs are rejected. Root must include all
transitive production/resource dependencies and applicable lock files. Missing
declared inputs cause capture failure, rather than a fresh claim. Manifest
changes require restarting the gallery with the regenerated manifest.

The default capture callback executes exactly this argv without a shell:

```text
./dev ui capture --scene <allowlisted ID> --scenario <allowlisted state> --output <new absolute PNG path>
```

Root's command must return nonzero on launch/build/screenshot failure, exit only
after writing and closing its output, and ensure all writers have stopped. On
success it must also write the sibling `<PNG stem>.json` receipt with exactly
`{"device":"actual device name or UDID","os":"actual runtime/version"}`.
Existing output/receipt paths and receipt symlinks are rejected. The new PNG path
is generated by the adapter under its canonical results session; browsers cannot
choose a path. The receipt records the native target, not the Mac host OS.

Open invokes exactly:

```text
./dev ui open --scene <allowlisted ID> --scenario <allowlisted state>
```

The native owner retains resource locking and simulator ownership. The gallery
serializes its own HTTP actions and watch capture on one executor. Reuse the
existing `scripts.devtools.process.run_process` implementation: default timeout
120 seconds, cancellation Event, owned process groups, bounded TERM/KILL cleanup,
closed redacted raw command logs, and canonical QA journal indexing. It neither
kills nor shuts down resources owned by other lanes. Ctrl-C/SIGTERM cancels the
active group; the server exits after that command returns. No recurring scheduler
or background native orchestrator is installed.

## Library and CLI

```python
from pathlib import Path
import json
from scripts.gallery import Gallery, GalleryServer, Manifest

root = Path("/absolute/worktree")
manifest = Manifest.parse(json.loads(Path("/path/native-scenes.json").read_text()), root)
gallery = Gallery(root, manifest)
server = GalleryServer(gallery, port=0)
try:
    print(server.url)  # Local capability URL; keep private.
    server.serve_forever(poll_interval=0.2)
finally:
    server.server_close()
    gallery.close()
```

Run from the repository root, after root implements the native command contract:

```sh
python3 -m scripts.gallery --manifest /path/native-scenes.json --port 0
python3 -m unittest discover -s tests/gallery -v
```

There is deliberately no default manifest or automatic initial capture. Click
`capture` for an allowlisted scene/scenario; that pair becomes the watch
selection. `--no-watch` disables source polling. `open` starts the real scene on
the owned device, where interaction happens through root's Device panel/native
workflow. The browser image is a static capture, not a touch-forwarded app.

`Gallery(root, manifest, capture=callback, open_scene=callback, journal=journal)`
supports integration/tests without replacing native orchestration. The capture
signature is `(scene: str, scenario: str, output: Path) -> CaptureIdentity`, called
synchronously; return only after all output writers close, or raise on failure.
`CaptureIdentity(device, os)` must describe the actual capture target. The open
signature is `(scene: str, scenario: str) -> None`; raise on failure. Callbacks
are trusted library dependencies, never request/manifest parameters. Production
defaults always use the fixed argv above. A caller using injected callbacks owns
their process timeout/cancellation and raw-log contract. Use the default native
adapter for subprocess work. `Gallery.close()` closes its journal and sets the
native cancellation Event; close it only after the single executor has stopped.

## HTTP boundary

Only IPv4 `127.0.0.1` binds are supported, including an ephemeral default port.
Every request checks loopback peer and exact `Host: 127.0.0.1:<port>`. `localhost`,
LAN/wildcard binds, foreign/null/duplicate Origin, cross-site fetches and alternate
hosts are rejected. No CORS headers are emitted; OPTIONS always fails.

`GET /` serves only a viewer shell, with a restrictive hashed-script CSP. The
unguessable bearer token is printed in a URL fragment, read into browser memory
and immediately removed from history. The shell contains no token or capture
data. There are no cookies or query-string tokens. Authenticated GET routes are
exactly `/api/state` and `/images/<opaque capture id>`. The latter serves only an
indexed successful PNG whose current bytes still match its recorded hash.
There is no static-directory route or arbitrary-file server.

Mutations are only `POST /api/capture` and `POST /api/open`, requiring a constant
time bearer-token check **and an explicit exact Origin matching the server**.
Body type must be `application/json`, at most 1024 bytes with a single explicit
Content-Length and no Transfer-Encoding. JSON has exactly `scene` and `scenario`;
duplicate keys, extra arguments, unknown IDs, paths, query routes and encoded
route variants fail closed. GET never mutates. Keep the printed local capability
URL private; local processes with the token have the gallery's narrow authority.

## Freshness, watch and evidence

Each completed attempt has an immutable JSON record containing HEAD commit,
source and lock SHA-256 fingerprint/inputs, nanosecond mtimes, start/end time,
status and error. Successful capture metadata additionally records device, OS,
capture time, absolute image path and SHA-256, previous image hash and
`image_changed`. That field compares encoded PNG bytes; it is not a perceptual
pixel-diff metric or proof that an expected UI change appeared. An identical PNG
may be a successful capture, while a changed PNG cannot turn a failed native
command into success. Inspect the actual image for visual acceptance.

`fresh` requires a successful closed native capture, valid PNG chunk structure
and CRCs, unchanged declared inputs/mtimes across capture, and an intact retained
image. Changed source/lock content or mtime makes a prior capture `stale`.
Capture failure retains the last good image and marks it `stale`; without one,
status is `failed`. An explicit failure remains stale until a new success.
`last_good` and `attempt` keep old image provenance separate from the failed
attempt. Deleted or modified image files are stale and never silently re-served.

Watch polls only the selected scene's explicit sources plus manifest locks.
Content hashes catch edits even when mtime is restored; mtime-only edits also
invalidate. It coalesces changes for a 0.3-second quiet interval before invoking
the same capture callback. Edits during a capture yield a stale result and a new
coalesced capture on a later tick. Unrelated sources do not trigger capture.
Failure alone does not cause a retry loop; another edit or manual capture does.

Immutable completed attempt records, closed PNGs/receipts and native logs are
indexed with path/hash through `tests/qa/journal.py`. PNG validation is performed
after callback completion. A failed partial output is retained as evidence but
never registered as a gallery image. Runtime artifacts live under the primary
checkout's `tests/results/gallery/<worktree hash>/<session>/`; raw process logs
live in canonical `tests/results/devtools/logs/`. SQLite remains the separate QA
Activity journal, never the app's user Activity database. Mutable metadata files
and live outputs are not indexed. Stop the executor before closing the journal.

## Verification boundary

Adapter tests use versioned inline synthetic PNG inputs and injected callbacks
or mocked process boundaries. They cover stale failure/last-good retention,
unchanged and changed image bytes, dependency/lock/mtime watch coalescing,
mid-capture edits, malformed PNGs/manifests, fixed argv, timeout/cancel forwarding,
authenticated routes, origin/Host/token/CORS rejection and traversal attempts.
They make no native visual or interaction claim.

No Xcode build, simulator launch, real scene capture, app source edit to new image,
direct interaction or physical-device acceptance was executed in this lane.
Root must validate those native journeys after integrating TodayScenes and
`./dev ui capture/open`. Static gallery tests do not satisfy that acceptance.
