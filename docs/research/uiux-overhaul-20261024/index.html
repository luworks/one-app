结论：推荐方向 B「一个输入框」，分两步走。第一步先做方向 A 里风险最低的一块：Today 的行补上“今天 / 明天 / 选日期”，逾期移到顶部，加一键整理。这一块只改 Today 一个功能区，不动数据结构和同步。10 个常用任务的总点击：现状 33，A 23，B 18（约少 45%）；需要用户做的决策：9 → 4 → 1。C 的点击数和 B 一样，但要拆掉 Apple 式的 Week 网格和 Clock tab，违背“先对齐 Apple 再超越”的路线，所以不推荐现在做。

复杂度从哪来

1. Today 只能看，不能改

Today 页的行菜单和左滑只有 Settle、Snooze 和删除；“今天、明天、取消日期”这几项只出现在 Reminders 和 Calendar 的行上。原因在 DayAgenda.attention：它是替换了标准菜单，而不是在标准菜单上追加。

2. 逾期被藏起来了

“Overdue (N)” 默认折叠，放在最底下。顶部那条红色的 “N overdue” 只在 showsWeekStrip 时渲染，而 Today 传的是 false，所以它是死代码。整理逾期只能在 Chat 里用。另外 Settings 里还能把逾期整个关掉，和原则 6 冲突。

3. 只藏不改的概念太多

Settle、Today Snooze、通知 Snooze、闹钟 Snooze：四种“先别管它”，其中三个叫 Snooze，意思各不相同。

4. 新建入口太多

+ 按钮在每个 tab 上手势不同（Today 页是“点一下出菜单”，其他 tab 是“点一下就新建”）。新建提醒有 4 个界面（Quick add、列表里的行内新建、TaskEditor、Chat 卡片），用了 3 种不同的时间选择器。

5. 三个“今天”

Today tab、Reminders 的 Today 智能列表、Calendar 的日视图；逾期也有 4 种看法。

6. 设置太多

约 37 个选择。多项控制的区块本来就是折叠的；有两个分区都叫 “Calendar”；智能列表的显示/隐藏在设置里和胶囊长按里各有一份。

三个方向

A · 整理保守 · 约 7 个 PR

IA 不变。删掉 Settle 和 Today Snooze，行的动作统一，逾期置顶并能一键整理，+ 只保留“点 = 新建”，只留一张新建表单，设置砍掉一半，搜索移到顶栏。

B · 一个输入框推荐 · A + 约 5 个 PR

4 个 tab 和 Apple 式屏幕都保留。底栏改成常驻输入框，同时管添加、提问和搜索。Today 加周条，可以左右滑到任意一天。

C · 一条时间线激进 · A + B + 约 8 个 PR

只剩「日程 / 列表」两个 tab。日程是一条无限时间线，月历和年历是缩放出来的，Clock 移进侧栏。和“先对齐 Apple”的路线冲突。

第一个 PR（建议）

“Today rows act”：Today 上提醒的长按菜单补上标准项（今天 / 明天 / 选日期 / 旗标），保留现有的 Settle 和 Snooze 不删；逾期从底部折叠区移到顶部一行，加“整理”按钮，直接打开现有的 Tidy 卡。只改 FeatureToday/DayAgenda.swift、TodayPlannerUI/Rows.swift 和 Ask 的入口参数，不碰数据结构、同步和闹钟编辑器。效果：“改期”3 次 → 2 次，“处理逾期”8 次 → 2 次。
