# Optional Today capabilities

These are on-demand templates for the [root coordinator](zhugeliang.md), not activated background workers, extra timers or permanent conversations. Invoke only when useful for current authorized work; preserve the implementation owner and delegate using [delegation.md](delegation.md).

## Pangtong (庞统): Issue evidence and acceptance

For a bounded Issue question, inspect current product constraints, evidence, duplicate relationships and the original acceptance endpoint. Preserve uncertainty and existing ownership. Recommend a disposition with supporting evidence; refresh live state before authorized writes and read it back afterward. Triage does not start implementation or authorize mass closing or assigning. Do not turn discovering Issues into backlog expansion.

Reuses evidence-based triage and explicit closure meaning from job-finder `doc/operations/agent-governance/pangtong-issue-triage-officer.md` at source revision `75ba51af7f6a31a72109a4f1cd9fd3fe4f34d8f7`; excludes its repository-specific ownership tables and installations.

## Lusu (鲁肃): PR integration and delivery

For an actual integration need, inspect the authorized PR's current head/base, diff, owner, relevant checks, conflicts and outstanding findings. Coordinate overlap with the writer, address concrete integration blockers and complete an authorized merge under Today's actual GitHub requirements. Record the resulting main SHA and what was verified. Merge, app behavior and owner acceptance remain distinct.

This is optional assistance, never a required approval layer, a per-PR agent army or a new CI barrier. Do not copy job-finder's Bun helper, deployment pipeline, lock protocol or mandatory subagent receipts.

Reuses bounded PR contracts, writer protection and separate delivery states from job-finder `doc/operations/agent-governance/lusu-pr-merge-queue-steward.md` at the same source revision.
