## Source inventory and redundancy

Exact input inventory: 5,439,631 resource bytes, of which eight 28-second mono
IMA4 CAF tones contribute 5,280,736 bytes (97.08%); cities 113,375 bytes / 952
records, app-icon PNG 42,214 bytes, catalog metadata 815 bytes, Shortcuts string
catalog 2,491 bytes. No custom fonts, third-party packages, vendored frameworks
or model weights were found. SDK libraries are linked system dependencies,
not their full SDK size inside the package.

No identical full-file or audio-payload duplicates were found. Tone duration and
size equality is not redundancy; all eight are reachable alarm/timer options.
31,040 bytes of CAF free-chunk padding is verified, but package savings and safe
repacking remain unmeasured. Shared sources enter app and two extension targets;
dead stripping and intent extraction prevent source-byte counts from predicting
binary savings. No asset is declared unused merely from its name.

Release **does exclude** the DEBUG-only TestDataset, CalendarDemoSeed, DevImport
and HealthDebugSeed implementations (18,205 source bytes). Fixture JSON and UI
test bundles are outside app target membership. Release **does retain** the
documented initial SampleData, Health mock/runtime test switches, in-memory and
temporary-store launch arguments, and appearance timing probe. These are source
reachability findings; normal launch does not activate test arguments. Migration
models and widget gallery samples are intentional compatibility/product content.
See the static audit for every resource, target, call site and uncertainty.

## Gap against top-tier iOS experiences

There are no authorized same-protocol competitor measurements in this baseline.
Numerical claims about Apple Calendar/Reminders/Clock, Overlap or other leading
apps would be invented. Their performance gap is **unknown**. The useful external
reference is Apple's platform guidance, not competitor scores:

- [Responsiveness](https://developer.apple.com/documentation/xcode/improving-app-responsiveness):
  propose <100 ms discrete response and <5 ms main-thread update work; budgets
  must be verified with signposts/Instruments, not XCTest tap wall time.
- [Launch](https://developer.apple.com/videos/play/wwdc2019/423/): aspirational
  ≤400 ms first frame; current process/onAppear and automation-ready measures
  have different boundaries and cannot directly prove this goal.
- [Hitches](https://developer.apple.com/documentation/xcode/understanding-hitches-in-your-app):
  ≤10 ms/s good; propose ≤5 ms/s, ideal zero. At 60/120 Hz frame intervals are
  16.67/8.33 ms; not all that time is available to app work.
- [App size](https://developer.apple.com/documentation/xcode/reducing-your-app-s-size):
  App Store Connect or a valid thinned export is needed for actual distribution
  numbers. A local ZIP is only a compressed proxy.
