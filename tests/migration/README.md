# Baseline storage contracts

Synthetic input generation lives in `ContractHarness.swift`; there is no private export or required temporary input. This directory is the fixture catalog for the migration lane (its ownership explicitly excludes `tests/fixtures/`). Large generated databases and captured sources belong in the canonical checkout's `tests/results/`, not Git.

```sh
python3 tests/migration/run.py
python3 tests/migration/run.py --reader-ref <integration-commit>
```

The writer always uses local commit `395376bb126fd7415ac6b44eee91b796eb8ca60c`. Sources are read with `git show`, hashed, and compiled unmodified with `swiftc`. No network, app build, simulator, signing, package/project mutation or app-container access is needed. `--reader-ref` compiles the same contract driver against a second committed source revision. It accepts a Git commit, not uncommitted edits. API/compiler failures are failures, not skipped compatibility checks. When both revisions match, one binary runs in separate writer and reader processes.

An output directory must not already exist. Failures keep their entire directory. The generator never deletes a database or invokes `openOrRecover`. Each run records commands, outcome, paths and artifact hashes through `tests/qa/journal.py` in `/Users/yuanlu/code/one-app/tests/results/activity.sqlite`. An explicit `--output` must be a new directory inside canonical results; other locations are rejected. The fixed journal path is intentional for this authorized local lane.

Each output contains:

- `baseline-source/`, `source-contract.json`: source inspection, file hashes, model names and candidate key literals. The key scan is discovery, not a complete runtime defaults schema; full captured source is authoritative.
- `writer/sources.json`, extracted Swift files, compiler binary and `run.log`: exact old writer source/harness hashes and actual commands. A separate `reader/` is present when the reader revision differs.
- `fixtures/activity.sqlite`, `activity.jsonl`, `activity.csv`, `task-snapshot.json`, `share-inbox.json`, `activity-outbox/*.jsonl`, `widget-snapshot.json`, `expected.json`: actual old-writer output, frozen after process exit.
- `fixture-manifest.json`: SHA-256 of every frozen artifact. Install/device IDs generated by production code and JSON object order may differ between generations; use the manifest from the actual run. Fixed synthetic logical IDs, dates, titles, checklist ID and recurrence values are in the driver.
- `reader-copy/`: disposable *retained* copy for reader assertions and interruption exercises. It never replaces the writer originals. `sqlite-contract.json` captures actual schema and relationships after reader assertions; it includes the outbox row inserted during verification.
- `result.json`: successful execution scope and explicitly missing platform gates. A failed run has no success result. `run.log` and the QA journal preserve its failure.

This runner adds retained cross-process writer/reader artifacts, not another copy of the existing unit suite. `ShareImportDurabilityTests`, `ShareInboxTests`, `ActivityStoreTests`, `ActivityRecorderTests` and `ActivityLedgerTests` remain the detailed branch tests. The share exercise uses production `ShareImport` and `ShareInbox` with a test-only SQLite metadata receipt adapter; it does **not** establish production SwiftData atomicity. The interleaved append is deterministic concurrency ordering, not simultaneous extension processes.

See [storage compatibility](../../docs/engineering/storage-compatibility.md) for baseline contracts, a known outbox failure boundary, and the required iOS bridge.
